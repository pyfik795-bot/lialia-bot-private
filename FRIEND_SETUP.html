Как получить и запустить «Ляля Бот»

Пошаговая инструкция без Python, PyCharm и HAPP: устанавливаем необходимые программы, добавляем собственные ключи и запускаем проект в Docker.

Windows x64WSL 2Git for WindowsDocker Compose

Что понадобится

Компьютер должен иметь 64-битную Windows, не менее 8 ГБ памяти и включённую аппаратную виртуализацию.

Устанавливаем

Git for Windows, WSL 2 и Docker Desktop. Python отдельно устанавливать не требуется.

Получаем от владельца

Очищенную папку проекта или адрес закрытого Git-репозитория. Ключи владельца в комплект не входят.

Сначала используйте DEMO-счёт. Не переключайте проект на реальные деньги, пока не проверены сигналы, объём позиции, стопы и тейк-профиты.

Что владелец удаляет перед отправкой

Этот раздел предназначен отправителю проекта. Очистить только API-ключи недостаточно.

Не удаляйте исходный рабочий проект. Очищайте только копию, подготовленную для друга.

1. Подготовить Windows

1

Откройте PowerShell от имени администратора

Нажмите «Пуск», введите PowerShell, нажмите правой кнопкой и выберите запуск от имени администратора.

2

Установите или обновите WSL 2

Вставьте команды по очереди:

PowerShell · администратор 
wsl --install
wsl --update
wsl --set-default-version 2
3

Перезагрузите компьютер

Если Windows сообщает, что виртуализация выключена, включите Intel VT-x/VT-d или AMD-V/SVM в BIOS/UEFI.

Если wsl --install пишет, что WSL уже установлен, это нормально — выполните остальные команды.

2. Установить Git

Скачивайте Git только с официального сайта. В установщике можно оставить рекомендуемые параметры.

Официальная загрузка Git ↗

Либо установите Git одной командой:

PowerShell 
winget install --id Git.Git -e --source winget

Закройте PowerShell, откройте заново и проверьте:

PowerShell 
git --version

3. Установить Docker Desktop

Нужна версия Docker Desktop для Windows x86_64 с движком WSL 2.

Скачать Docker Desktop ↗
1

Запустите установщик

Выберите рекомендуемую установку для текущего пользователя и оставьте включённым WSL 2 backend.

2

Запустите Docker Desktop

Дождитесь сообщения, что Docker Engine работает. Регистрация Docker Hub для локального запуска не обязательна.

3

Проверьте установку

Откройте новый PowerShell:

PowerShell 
docker version
docker compose version
Если обе команды показывают версии клиента и сервера, Docker готов.

4. Получить проект

Используйте один из двух способов. Не запускайте проект прямо из ZIP-архива или с флешки.

Вариант A — владелец прислал ZIP

  1. Распакуйте архив полностью.
  2. Переместите папку, например, в C:\LialiaBot.
  3. Проверьте наличие compose.yaml, Dockerfile и config.py.

Вариант B — закрытый Git-репозиторий

PowerShell · замените ссылку 
cd C:\
git clone АДРЕС_РЕПОЗИТОРИЯ LialiaBot
cd C:\LialiaBot
Не публикуйте проект с заполненным config.py в открытом репозитории.

5. Заполнить собственные ключи

Откройте C:\LialiaBot\config.py в Блокноте или редакторе кода. Не используйте ключи другого человека.

ПараметрЧто указать
API_ID и API_HASHСобственные данные Telegram API с my.telegram.org.
BOT_TOKENТокен своего бота от официального @BotFather.
ALLOWED_USERNAMESСвой Telegram username.
BYBIT_API_KEY / SECRETСобственные API-ключи Bybit. Начинать только с DEMO.
DEMOПри первом запуске обязательно True.
WEB_PASSWORDНовый уникальный пароль веб-панели.
Никому не отправляйте заполненный config.py. API-ключ Bybit для торговли не должен иметь разрешения на вывод средств.

6. Первый запуск

1

Создайте служебный .env

Откройте PowerShell в папке проекта:

PowerShell 
cd C:\LialiaBot
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\prepare-docker.ps1"
2

Соберите Docker-образ

Первая сборка загружает зависимости и может занять несколько минут. Сам торговый бот пока не запускается.

PowerShell 
docker compose build
3

Авторизуйте свой пользовательский Telegram-аккаунт

Это отдельная авторизация аккаунта, который читает каналы, а не Telegram-бота. Введите номер телефона в международном формате, код из Telegram и облачный пароль 2FA, если он включён.

PowerShell · интерактивный вход 
docker compose run --rm app python -c "from main import build_akk_client; c=build_akk_client(); c.start(); print('Telegram authorization OK:', c.is_user_authorized()); c.disconnect()"
Код входа и пароль 2FA вводятся только в своём PowerShell. Никому их не отправляйте. После успешного входа рядом с проектом появится новый BOT.session.
4

Запустите весь проект

Теперь можно включить приложение в фоновом режиме.

PowerShell 
docker compose up -d
5

Проверьте состояние

Контейнер lialia-bot должен работать.

PowerShell 
docker compose ps
docker compose logs --tail=100 app
6

Откройте интерфейсы

В браузере: http://localhost:8080. В Telegram откройте своего бота и отправьте /start.

Одновременно запускается только один экземпляр с одним BOT_TOKEN и одной BOT.session. Иначе Telegram вернёт Conflict.

Управление проектом

При запуске бот сам проверяет origin/main и применяет безопасное fast-forward обновление. Для закрытого репозитория доступ GitHub должен быть настроен заранее. Если проверка не удалась, запускается текущая версия; журнал находится в logs/updater.log.
ДействиеКоманда в C:\LialiaBot
Показать состояниеdocker compose ps
Смотреть журналdocker compose logs -f app
Перезапустить приложениеdocker compose restart app
Остановить всёdocker compose down
Запустить сноваdocker compose up -d
Обновить из Git вручнуюgit pull --ff-only
Пересобрать после изменения зависимостейdocker compose up -d --build
Не используйте docker compose down -v: флаг -v удаляет служебные Docker-тома.

Частые проблемы

Docker-команды не работают
Запустите Docker Desktop и дождитесь готовности Engine. Затем откройте новый PowerShell и повторите docker version.
WSL требует обновление
Откройте PowerShell от администратора, выполните wsl --update и перезагрузите Windows.
prepare-docker.ps1 открылся в Блокноте
Не запускайте файл двойным нажатием. Используйте указанную выше команду powershell.exe -File ....
Telegram пишет Conflict
С тем же BOT_TOKEN уже запущен другой экземпляр. Остановите его.
Сайт localhost:8080 не открывается
Выполните docker compose ps и docker compose logs --tail=200 app. Проверьте, не занят ли порт 8080.
Сигналы не приходят
Проверьте авторизацию Telegram, включённые каналы, назначенные парсеры и доступность Telegram и Bybit из сети друга.
Если ошибка осталась, скопируйте вывод docker compose ps и docker compose logs --tail=200 app. Перед отправкой журнала убедитесь, что в нём нет токенов и ключей.
