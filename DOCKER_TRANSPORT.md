# Перенос «Ляля Бот» на другой компьютер

Контейнер содержит только код и Python-зависимости. Рядом с `compose.yaml`
остаются `config.py`, `BOT.session`, JSON-состояние и логи. Поэтому обновление
или пересборка образа не теряет активные сделки, историю и авторизацию Telegram.

## Что установить на новом ПК

1. Docker Desktop с поддержкой Linux-контейнеров.
2. В BIOS должна быть включена виртуализация; в Windows — WSL 2.

Python, PyCharm и зависимости проекта на новом ПК не требуются.

## Подготовка флешки

Перед копированием штатно остановите работающего бота. Это важно для целостной
копии SQLite-файла `BOT.session` и состояния активной сделки.

Откройте PowerShell в папке проекта и выполните:

```powershell
.\export-to-flash.ps1 -Destination "E:\LialiaBot" -IncludeDockerImages
```

Замените `E:` на букву флешки. Папка назначения должна быть пустой.

Параметр `-IncludeDockerImages` создаёт `docker-images.tar`. Такой комплект
можно запустить на другом ПК без повторной загрузки образов из интернета.
Без этого параметра комплект будет меньше, но первая сборка скачает базовые
образы, зафиксированные исходники MTProxy и Python-пакеты.

## Запуск на новом ПК — офлайн-комплект

Скопируйте папку с флешки на внутренний диск, например в `C:\LialiaBot`.
Не рекомендуется круглосуточно запускать бота прямо с флешки.

```powershell
cd C:\LialiaBot
docker image load --input .\docker-images.tar
docker compose up -d --no-build
```

Панель откроется по адресу: `http://localhost:8080`.

## Запуск с загрузкой образов из интернета

```powershell
cd C:\LialiaBot
.\prepare-docker.ps1
docker compose up -d --build
```

`prepare-docker.ps1` извлекает существующий секрет MTProxy из `config.py` и
создаёт локальный `.env`. Файл `.env` не включается в Docker-образ.

MTProxy собирается из официального репозитория Telegram на зафиксированном
commit, а не из их устаревшего готового образа. При старте он обновляет файлы
конфигурации Telegram и при временном сетевом сбое использует последнюю копию.

## Основные команды

```powershell
docker compose ps
docker compose logs -f app
docker compose restart app
docker compose down
docker compose up -d
```

`docker compose down` не удаляет файлы состояния. Не используйте флаг `-v`,
если не хотите удалить служебный том MTProxy.

## Проверка после переноса

1. `docker compose ps` показывает `lialia-bot` и `lialia-mtproxy` как запущенные.
2. На сайте отображаются DEMO/REAL, баланс и активные сделки.
3. В Telegram приходит уведомление «Ляля Бот запущен».
4. В разделе сделок восстановилась позиция, если она была открыта при переносе.

## Важные замечания

- Одновременно должен работать только один экземпляр бота с этим Telegram-токеном.
- Перед первым запуском на новом ПК остановите старый экземпляр.
- Веб-панель по умолчанию привязана к `127.0.0.1` и доступна только на самом ПК.
- Время Windows должно синхронизироваться автоматически: Bybit строго проверяет
  временные метки запросов.
- Резервная копия — это вся папка проекта без `.venv`, `.git` и логов.

## Почему здесь нет отдельной базы данных

Проект рассчитан на один процесс и небольшой объём локального состояния.
JSON-файлы уже защищены блокировками внутри приложения, а Telethon использует
собственную SQLite-сессию. PostgreSQL усложнил бы перенос, резервное копирование
и восстановление активной сделки, не дав практической пользы в текущем масштабе.
